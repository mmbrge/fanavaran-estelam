# اتوماسیون فناوران — استعلام عدم خسارت

خودکارسازی عملیات‌های تکراری نرم‌افزار بیمه‌ی **فناوران** (`Bime.exe`) بر اساس
ردیف‌های هایلایت‌شده‌ی یک فایل اکسل، با تأیید نهایی دستیِ کاربر بین هر ردیف.

فلوی اصلیِ کامل: **دریافت استعلام عدم خسارت** → پیدا کردن بیمه‌گذار → انتخاب آخرین
ردیف با «شماره الحاقیه = ۰» → گرفتن خروجی PDF → ذخیره در پوشه‌ی همان شخص
(بر اساس سال/ماه شمسی) → نوشتن نتیجه در ستون «وضعیت» اکسل (سبز = موفق، قرمز = خطا).

> ⚠️ **این برنامه فقط روی ویندوز کار می‌کند** (به `pywin32`/`pyautogui` و پنجره‌ی
> واقعی `Bime.exe` وابسته است). روی لینوکس/مک اجرا نمی‌شود.

---

## نحوه‌ی کار (خلاصه)

1. در اکسل، ردیف‌هایی را که می‌خواهی پردازش شوند با **رنگ زرد** (Fill زرد) هایلایت کن.
   ستون «بیمه گذار» باید مقداری مثل `نام خانوادگی کد 12345678` داشته باشد؛ برنامه
   خودش «کد» را از متن بیرون می‌کشد.
2. فناوران را باز و لاگین کن و پنجره را **maximize** کن.
3. اسکریپت را اجرا کن؛ برای هر ردیف زرد، ۱۷ مرحله را انجام می‌دهد و بعد از هر ردیف
   منتظر Enter تو می‌ماند (مگر با `--auto`).

## نصب

```bash
pip install -r requirements.txt
```

علاوه بر پکیج‌های پایتون، این دو را هم جداگانه روی ویندوز نصب کن (برای OCR گرید):

- **Tesseract-OCR** با زبان فارسی (`fas.traineddata`) — <https://github.com/UB-Mannheim/tesseract/wiki>
- **Poppler for Windows** (مسیرش را به `PATH` اضافه کن) — برای `pdf2image`

## مراحل راه‌اندازی

### ۱) تست خواندن اکسل (بدون نیاز به باز بودن فناوران)

```bash
python excel_utils.py --file "sample_data.xlsx" --insurer-col "بیمه گذار"
```

اگر رنگ زردِ فایلِ تو با لیست `YELLOW_ARGB_CANDIDATES` در `excel_utils.py` فرق داشت،
با `--debug-colors` رنگ واقعی سلول‌ها را ببین و به آن لیست اضافه کن.

### ۲) کالیبراسیون مختصات نقاط ۱ تا ۱۷

چون کنترل‌های فناوران با UI Automation قابل‌شناسایی نیستند، مختصات هر نقطه را
یک‌بار دستی ثبت می‌کنیم (نسبت به گوشه‌ی پنجره):

```bash
python calibrate_coords.py --interactive
```

راهنمای کاملِ اینکه هر نقطه (۱ تا ۱۷) چیست در فایل
[`راهنمای_کالیبراسیون.md`](./راهنمای_کالیبراسیون.md) آمده است.

### ۲-ب) بهتر: پیدا کردن مراحل از روی تصویر (بدون مختصات)

برای هر مرحله‌ای که برایش تصویر بسازی، فلو دکمه رو **از روی تصویرش** روی صفحه
پیدا می‌کنه (هرجا که باشه) و تا ظاهر شدنش صبر می‌کنه؛ بقیه‌ی مراحل مثل قبل با
مختصات. این برای دکمه‌هایی که جاشون عوض می‌شه (مثل ▼ گروه «چاپ» که بسته به ردیف
انتخاب‌شده جابه‌جا می‌شه) لازمه.

```
python capture_template.py --label 9
```

چند ثانیه وقت داری صفحه رو آماده کنی (مثلاً منو رو باز کنی)، بعد عکس گرفته می‌شه
و روی همون عکس ثابت دور دکمه کادر می‌کشی. کمی از متن کنار دکمه رو هم بگیر تا
تصویر یکتا باشه؛ ابزار اگه تصویر جای دیگه‌ی صفحه هم تکرار بشه هشدار می‌ده.
تصاویر توی پوشه‌ی `templates/` ذخیره می‌شن (برای سیستم دیگه با همون رزولوشن و
مقیاس صفحه، همین پوشه رو کپی کن).

**تصویر وضعیت «ارسال به مالی» (برای انتخاب ردیف درست در مرحله‌ی ۸):**

```
python capture_template.py --label status_ok
```

دور متن «ارسال به مال...» توی ستون «وضعیت» یکی از ردیف‌ها کادر بکش. از این به بعد
مرحله‌ی ۸ «آخرین ردیفی که الحاقیه = 0 **و** وضعیت = ارسال به مالی» رو انتخاب می‌کنه
(و پیش‌نویس‌های «محاسبه نشده» رد می‌شن).

**تصاویر پنجره‌ی «جست و جو» (مرحله‌ی ۷، با تأیید هر قدم):** پنجره‌ی جستجو رو باز کن و بساز:

```
python capture_template.py --label search_dialog   (لازم: عنوان «جست و جو» بالای پنجره)
python capture_template.py --label search_apply    (لازم: دکمه‌ی «اعمال»)
python capture_template.py --label search_clear    (اختیاری: لینک «حذف همه فیلترها»)
python capture_template.py --label search_field    (اختیاری: عنوان «بیمه گذار» + فیلدش؛ کلیک توی فیلد)
```

برنامه منتظر می‌مونه پنجره باز بشه، «اعمال» رو از روی تصویر می‌زنه، منتظر بسته شدن
پنجره می‌مونه و بعد چک می‌کنه **گرید واقعاً عوض شده باشه**. اگه عوض نشده باشه (فیلتر
بیمه‌گذار اعمال نشده)، یه‌بار با صبر بیشتر تکرار می‌کنه و بعد خطای واضح می‌ده؛ به‌جای
خوندن گرید قبلی و ذخیره‌ی PDF شخص اشتباه.

**تصاویر مراحل ۱۴ تا ۱۷ (بستن گزارش و پاک کردن فیلتر برای ردیف بعد):**

| مرحله | چی رو بگیری |
|---|---|
| `14` | متن «چاپ استعلام خسارت بدنه» + × کنارش (کلیک روی ×) — با فرم گزارش باز |
| `15` | آیکون فیلتر بالای گرید (وقتی فیلتر فعاله، با نقطه‌ی قرمزش) |
| `16` | لینک «حذف همه فیلترها» توی پنجره‌ی جستجو |
| `17` | دکمه‌ی «اعمال» — همون `search_apply`؛ کافیه `search_apply.png/json` رو به اسم `17.png/json` کپی کنی |

`16` رو به اسم `search_clear` هم کپی کن تا جستجوی هر ردیف (حتی بعد از خطا) با فیلتر
پاک شروع بشه. با تصویر `14`، برگشت به حالت اولیه بعد از خطا فرم گزارش باز مونده رو
هم می‌بنده.

### ۳) کالیبراسیون گرید (برای مرحله‌ی ۸: پیدا کردن ردیف صفر با OCR)

با یک نتیجه‌ی جستجوی نمونه (حداقل ۲–۳ ردیف) روی صفحه:

```bash
python calibrate_grid.py
```

### ۴) اجرای فلوی کامل

```bash
python run_no_claim_flow.py --excel "فایل.xlsx"
```

گزینه‌ها:

| گزینه | توضیح |
|---|---|
| `--select yellow` | (پیش‌فرض) ردیف‌های هایلایت‌زرد را پردازش کن |
| `--select white` | به‌جای زرد، ردیف‌های بی‌رنگ/سفید را پردازش کن |
| `--confirm` | بعد از هر ردیف منتظر Enter بمون (پیش‌فرض: همه‌ی ردیف‌های زرد خودکار و بدون تأیید) |
| `--retries 2` | اگه ردیفی خطا داد، فناوران به حالت اولیه برمی‌گرده و ردیف از مرحله‌ی ۱ تا این‌قدر بار دیگه تکرار می‌شه |
| `--max-consecutive-failures 3` | اگه این‌همه ردیف پشت‌سرهم شکست خوردن، اجرا متوقف می‌شه |
| `--debug` | چاپ جزئیات OCR گرید برای عیب‌یابی مرحله‌ی ۸ |
| `--print-mode export` | (پیش‌فرض) ذخیره‌ی PDF با دکمه‌ی Export To PDF، بدون مختصات |
| `--print-mode print` | ذخیره‌ی PDF با پرینتر Microsoft Print to PDF، بدون مختصات |
| `--print-mode coords` | روش قدیمی پرینت با نقاط ۱۱ تا ۱۳ |

> در حین اجرا **دست به موس/کیبورد نزن**. برای توقف اضطراری، موس را به گوشه‌ی
> بالا-چپ صفحه ببر (FailSafe فعال است).

## نکات مهم و محدودیت‌ها

- **`coords.json` مخصوص همان کامپیوتر و همان اندازه‌ی پنجره است.** اگر رزولوشن،
  مقیاس صفحه (DPI)، یا اندازه‌ی پنجره عوض شود، همه‌ی کلیک‌ها جابه‌جا می‌شوند و باید
  دوباره کالیبره کنی. برنامه قبل از شروع، اختلاف اندازه‌ی پنجره را هشدار می‌دهد.
- برای اجرا روی سیستم‌های دیگر بدون کالیبراسیون مجدد، به روش‌های مبتنی‌بر تشخیص
  تصویر/عنصر نیاز است (در بخش «مسیر توسعه» پایین).

## مسیر توسعه‌ی بعدی (پیشنهادی)

- جایگزینی مختصات ثابت با **تشخیص تصویری دکمه‌ها** (template matching با
  `pyautogui.locateOnScreen` یا OpenCV) تا روی هر سیستم/رزولوشن بدون کالیبراسیون
  کار کند.
- بررسی امکان کنترل مبتنی‌بر پیام پنجره (pywinauto با backend مناسب) به‌جای کلیک
  فیزیکی، تا موس کاربر آزاد بماند.
